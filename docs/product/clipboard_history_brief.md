# Rust Seek 剪切板历史 — 需求简报（L2-A）

日期：2026-10-31　状态：待用户确认（本文件为事实与待确认项，不含实现细节）

## 1. 用户与要解决的问题

- 用户：本机日常用户（本人），已在用 rust-seek 的 `Alt+Space` 全盘文件名搜索。
- 问题：复制过的文本/截图过一会儿就找不回来；Windows 自带剪贴板历史（`Win+V`）只保留纯文本与位图且容量小、不能搜索、不能按需删除。
- 目标：在 rust-seek 内提供一个可被 `Ctrl+Shift+V` 呼出的剪切板历史面板，复用现有搜索窗与 UI 交互，不新增常驻进程。

## 2. 范围

**做**
- 监听系统剪贴板变化，记录**文本**与**图片**两类条目。
- `Ctrl+Shift+V` 全局热键呼出面板，切到「剪切板」模式（复用主搜索窗）。
- 面板：列表 + 搜索过滤 + 文本预览 / 图片缩略图。
- 选中条目 → 仅写回系统剪贴板（不自动粘贴），面板关闭。
- 单条删除；托盘「暂停记录」开关；容量上限与最旧淘汰。

**不做**
- 不做自动粘贴（不模拟 Ctrl+V），不接管目标程序焦点。
- 不做云同步、跨设备、多机共享。
- 不做富文本 / HTML / 文件路径列表等额外格式（只文本 + 位图）。
- 不做按应用黑名单（密码管理器等）——只提供全局暂停开关（见待确认 2）。
- 不改动现有搜索流程与索引行为。

## 3. 成功标准（可验收）

1. 在任意程序 `Ctrl+C` 一段文本，1 秒内可在面板看到该条目，选中回车后能粘贴到目标程序。
2. 截图工具复制图片后，面板显示缩略图；选中后可在画图/聊天窗口直接 `Ctrl+V` 贴出。
3. 面板内输入关键字可过滤历史条目；`Esc` 关闭；`Del` 删除选中条目，重启程序后删除结果仍生效。
4. 复制同一内容连续两次只保留 1 条；超过上限淘汰最旧，历史文件大小有界。
5. 托盘「暂停记录」打开后，新增复制不再入库；关闭后恢复。
6. 关闭剪切板历史功能（或暂停）时，原有文件名搜索的速度与行为无变化。

## 4. 主路径与关键失败 / 人工兜底

主路径：在任意程序复制 → 系统剪贴板更新 → 监听器收到通知 → 过滤（空/超长/连续重复）→ 落盘 → `Ctrl+Shift+V` 呼出面板 → 浏览/搜索选中 → 写回剪贴板 → 到目标程序 `Ctrl+V`。

失败与兜底：
- 剪贴板被其他程序独占打开 → 本次跳过，不阻塞、不影响搜索。
- 单条内容过大（超长文本 / 超大位图 / 图片解码失败）→ 跳过本次记录。
- 热键被占用或注册失败 → 托盘菜单提供「剪切板历史」入口兜底。
- 历史文件损坏或写盘失败 → 以空历史启动并可继续记录（不崩、不影响搜索）。
- 用户隐私场景 → 托盘一键暂停记录。

## 5. 关键约束

- 现有技术栈：Rust + eframe/egui 0.31，Windows 专属（已依赖 windows-sys 0.59、global-hotkey 0.9、tray-icon 0.26）；不引入新的重量级运行时或数据库。
- 存储落本机 `%LOCALAPPDATA%\rust-seek\clipboard\`，与索引缓存同根目录；纯文件，原子写。
- 与 `Alt+Space` 搜索共存：热键管理器已存在，需确认 `Ctrl+Shift+V` 是否已被其他软件占用。
- 开机自启动方式不变（应用内 `RegisterHotKey`，非 .lnk 热键）。
- 只做 Windows；不承诺 macOS/Linux。

## 6. 借鉴调研（GitHub，1 回合）

**借鉴**
- `Slackadays/Clipboard`（C++，5.9k★）：以「快捷键呼出 + 搜索 + 条目删除」为核心交互，证明面板复用搜索框是主流做法。
- `jimuzhe/tiez-clipboard`（Rust/Tauri，3.0k★）：Rust 侧做剪贴板历史的可行路径，图片按文件存储、文本入库的混合存储模型可直接沿用。
- `ChurchTao/clipboard-rs`（Rust，182★）：提供文本/图片读取 + 变化监听（monitor）的统一 API，可作为 `arboard` 的备选实现。
- `1Password/arboard`（Rust，979★）：文本/图片读写成熟稳定，但**不提供**变化监听，监听需自己用 Win32 消息窗实现。

**自研**
- Win32 `AddClipboardFormatListener` + 隐藏消息窗（`WM_CLIPBOARDUPDATE`）的监听线程：与现有 `integration.rs`（热键/托盘）同层，可控且无新依赖。
- 历史面板直接复用 egui 主窗口与现有搜索交互，不引入 WebView。

**不采用**
- `PasteBar/PasteBarApp`（TS/Electron）与 `Windows-11-Clipboard-History-For-Linux`：前者体积与运行时过重，后者是 Linux 目标，均不适配本机 Windows + 原生 GUI。
- Windows 自带 `Win+V`：容量与检索能力不足，且无法与 rust-seek 搜索统一。

**对架构的影响**
1. 监听 → 过滤 → 落盘必须与 GUI 线程解耦（后台线程 + 消息窗），否则会拖慢搜索窗口唤起。
2. 存储用「history.json + images/*.png」而非嵌入式数据库，避免引入 SQLite 依赖，同时便于用户直接查看/清理。
3. 面板复用主搜索窗意味着需要一套「模式切换」（搜索 / 剪切板），模式内沿用同一套键盘导航。
